# Plan: Reorganize Dashboard Navigation into a Professional SaaS Structure

## Context

The current sidebar is a mix of Tyro's generic admin scaffold items (Dashboard → Tyro's "Total Users/Roles/Privileges" page, System Settings → smtp/system split, Media, Examples, Checkpoints, Emailer, etc.) plus our custom screens added incrementally without a cohesive information architecture. The result reads as "Tyro with extras bolted on." The goal is a sidebar that feels like a purpose-built SaaS product — grouped by user intent, no Tyro internals exposed, and the first thing the user sees matches what they actually need.

**No new pages are built.** All existing routes and controllers stay as-is. This is pure sidebar + landing-page reorganization.

## Landing Page Fix: Admin sees Analytics, User sees Billing Overview

The Tyro `/dashboard` index shows admin stats (users/roles/privileges counts) which is Tyro-internal, not SaaS metrics.

**Fix:** In `config/tyro-dashboard.php`, set the `dashboard_redirect` option if it exists, OR add a route override that intercepts `GET /dashboard` before the Tyro package and redirects based on role:

In `routes/web.php`, **before the Tyro package routes load**, add inside the `auth` middleware group:

```php
// Redirect /dashboard to the right starting page for the role
Route::get('dashboard', function (Request $request) {
    $user = $request->user();
    if ($user->hasAnyRole(['admin', 'super-admin', 'finance', 'support'])) {
        return redirect()->route('dashboard.overview');
    }
    return redirect()->route('dashboard.billing');
})->middleware(['auth'])->name('dashboard.home');
```

This overrides the Tyro `GET /dashboard` route (Laravel processes app routes before package service-provider routes, or we can ensure priority via the existing route group order).

## Sidebar Active-State Pattern

The existing pattern in user-sidebar is:
```php
request()->routeIs('dashboard.billing') ? 'active' : ''
```

For billing sub-pages, use `request()->routeIs('dashboard.billing*')` to keep Billing active when viewing plans, invoices, etc.
