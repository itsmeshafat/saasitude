# Plan (reviewed): Build the Project Design System on the "SAAS Growth" Foundations

## Context — what the brief actually demands

Re-reading the brief properly: it is a **guideline-authoring specification**, not a color list. Deliverables must follow its Required Output Structure (Context → Tokens → Component rules with anatomy/variants/**8 mandatory states**/responsive → **testable** accessibility criteria → tone standards → anti-patterns → QA checklist), use semantic tokens only ("must"), forbid one-off spacing/type exceptions ("must not"), and cover the component inventory (links 83, cards 31, buttons 28, lists 20, navigation 3, inputs 2 — mapped to OUR components). **Content (pages, copy, features, routes) does not change**; the design system — tokens, states, density, docs — is adopted completely. User decisions retained: dark default + derived light; glassmorphism kept (recolored).

## Phase A — Foundations (semantic tokens, both modes)

**A1. Color** (`shadcn-theme.blade.php` canonical; mirrored in `app.css`/`public.css`).

Dark (default — brief values verbatim): `--background #000000` (surface.base) · `--foreground #ffffff` (text.tertiary) · `--card/--glass rgba(8,38,21,.55)`, `--glass-strong .78`, `--popover .9` (surface.muted) · `--glass-border rgba(229,231,235,.2)` · `--primary #c6fb4b` (surface.strong) with `--primary-foreground #0a1616` (dark-on-lime, AA ≈13:1) · `--muted-foreground #9ba5a1` (text.inverse, ≈7:1 on black) · `--secondary/--muted` surface.muted @ .6–.7 · `--accent` lime 10% · `--border #e5e7eb @15%`, `--input @18%` (border.default adapted for dark) · `--chart-1..5: #c6fb4b/#ffffff/#9ba5a1/#2d5a3f/#3b82f6` · mesh recolored (lime `.10` + deep-green blobs on black).

Light (derived, documented): `#ffffff` bg · `#0a1616` fg (text.secondary) · white-glass alphas · `--muted-foreground #52645c` (derived — brief's #9ba5a1 fails AA on white) · `--border #e5e7eb` solid. Retained extensions (brief silent): `--destructive` red, `--warning` amber, `--info` — logged as deviations.

**A3. Spacing scale — mapped and normalized** (`--space-1..8` = 3/4/5/6/8/10/12/16). Applied to system-owned CSS (`.card` padding 24→16 = space-8, `.stats-grid` gap 16→12 = space-7, `.filters-bar` gap 12→10, `.page-content` 32→16 padding + page-header spacing) and a **view sweep** normalizing Tailwind spacing to the scale (mb-6 24px → mb-4 16px; gap-6 → gap-4; gap-4 → gap-3 12px where card-internal). Documented mapping table prevents future one-offs.

**A4. Radius/Shadows/Motion.** Radius tokens `--radius-xs 2 / sm 8 / md 12 / lg 16 / xl 9999`; base `--radius` 12 (md), pills use xl. Shadows are **rings** per brief: `--shadow-1` (surface.muted 1px ring — cards on dark), `--shadow-2` (white 1px ring — elevated), `--shadow-3` (blue 50% — focus); map to `.card` ring treatment + focus. Motion `--duration-instant/fast/normal 150/200/300` wired into `.btn`, `.card`, `.sidebar`, dropdown/toast transitions.

**A5. Dark default**: public pre-paint script + Tyro `getTheme()` fall back to `dark` when no saved preference.

## Phase B — Component rules + implementation deltas

Inventory mapped to the brief's density, each specified with anatomy/variants/**default, hover, focus-visible, active, disabled, loading, error** states, responsive + keyboard/pointer/touch behavior, long-content/overflow/empty handling:

- **Buttons (28)** — `x-ui.button` (`.btn*` classes): add `loading` prop (spinner, `aria-busy`, disabled), verify all 8 states incl. focus-visible ring (shadow.3); long-label `white-space:nowrap`→`min-width` handling documented.
- **Links (83)** — `.sidebar-link`, `.tab-link`, breadcrumb, table links, `btn-link-btn`: hover/focus-visible/active states unified; icon+label truncation rules.
- **Cards (31)** — `.card`, `x-ui.card`, stat-cards, plan-cards, chart panels: ring shadow-1, glass surfaces, loading (skeleton shimmer token) + empty states (already `x-ui.empty-state`), overflow rules.
- **Lists/tables (20)** — `.table`, data-rows, notification lists: zebra/hover states, long-cell truncation (`truncate` + title), empty/loading (skeleton rows), sticky header on scroll where `.table-container` scrolls.
- **Navigation (3)** — sidebar, topbar (incl. notification bell), tabs: active/hover/focus states, keyboard traversal (bell dropdown Esc/arrow keys added), mobile behavior documented.
- **Inputs (2)** — `x-ui.input`/`select` + `.form-*`: all states incl. error (`.form-error`) and disabled; loading n/a documented.
- **Our extras** (beyond brief's count — specified too): badges/status-pill, usage-meter, charts (line/donut/bars re-tokened), pagination, modals/confirm dialogs, toasts, alerts.

Implementation deltas beyond Phase A: button loading, bell keyboard support (Esc/arrows), table skeleton-loading utility, focus-visible globals (`:focus-visible { outline:2px solid var(--ring); offset 2px }` + sweep for bare `outline:none`), `.form-radio` accent lime.

## Phase C — Documentation: rewrite `MASTER.md` in the brief's exact Required Output Structure

1) Context & goals (design intent sentence) · 2) Tokens & foundations (full tables above incl. deviations) · 3) Component rules (Phase B specs) · 4) Accessibility acceptance criteria — **pass/fail testable**: contrast ratios (dark: 21:1 body, ≈13:1 primary pair, ≈7:1 muted; light ≥4.5:1 all text pairs — computed values recorded), visible focus on 100% of interactive elements, keyboard-complete flows · 5) Content & tone (content unchanged; concise/confident tone rules for future copy) · 6) Anti-patterns & prohibited (no raw hex in components, no off-scale spacing/type, no hidden focus, no local visual exceptions) · 7) Migration notes (Cobalt Glass → this system; Aeonik licensing; component renames none) · 8) QA checklist. All rules use must/should per Quality Gates. Memory updated.
