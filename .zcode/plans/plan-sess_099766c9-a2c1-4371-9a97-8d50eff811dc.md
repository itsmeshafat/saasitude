# Plan: Polish Basic Pages + Charts, Reports & Export System

## Context

A full audit of all 28 custom views found: **8 basic-looking pages** (including a literal placeholder), **zero charts anywhere**, **no KPI trend indicators**, and **no export capability on any table**. Tyro ships an underused component kit (published `stat` with change/trend arrows, `progress`, `data-table`) and — importantly — **its own zero-dependency chart pattern** (inline SVG paths themed by CSS variables, from its examples pages). We'll follow that pattern rather than adding chart.js, so charts auto-theme in dark mode with no new npm/composer dependencies.

---

## Workstream 1 — Chart infrastructure (zero-dependency)

- **`app/Support/SvgChart.php`** — small helper: `linePath(array $values, int $w = 600, int $h = 180)` builds a smooth SVG path from integer/float series; `areaPath()` (line + baseline close); `donutSegments(array $values)` returns stroke-dasharray circle segments; `barHeights(array $values)` returns percentages. Pure math, unit-testable.
- **Blade components** `resources/views/components/chart/{line,donut,bars}.blade.php` — wrap inline SVG, colors via `var(--primary)`, `var(--chart-2..5)`, dark-mode safe like all tokens. Props: `values`, `labels`, `height`, `color`.

## Workstream 2 — Analytics page: real charts + reports

`AdminOverviewController@show` gains computed series (from `payments` + `subscriptions` tables):
- **Revenue by month** (12 months, sum of succeeded payments) → area/line chart on the Analytics page
- **New subscriptions per month** → CSS bar chart
- **Gateway mix** (succeeded payments by gateway) → donut with legend
- **Month-over-month deltas** → `stat-change` up/down arrows on the existing stat cards (use the published `stat` component's change/trend props)

## Workstream 3 — Export system (CSV + PDF report)

- **`app/Http/Controllers/Admin/ExportController.php`**: streaming CSV via `fputcsv` (memory-safe, no packages): `payments`, `invoices`, `subscriptions`, `workspaces` — each honors the page's current filters (search/status/gateway via query string) and date-range params. Route group `admin/exports/{type}` under existing admin middleware, named `admin.exports.*`. Gate CSV of payments behind `billing.view` privilege.
- **"Export CSV" buttons** added to the `filters-bar` on payments-admin, subscriptions-admin, workspaces-admin, admin invoices (carry current filter query).
- **Monthly report PDF** (`GET admin/exports/report?month=YYYY-MM`): dompdf via the established `GenerateInvoice` pattern (`Pdf::loadView('admin.reports.monthly')`) — table-based summary (no SVG in dompdf): revenue, new/canceled subs, gateway split, failed payments. "Download report" button on Analytics.
